# dsh-llm-adapters

把 **Loomy（讯飞）** 与 **商汤小浣熊** 接进
[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）。

- **微信扫码登录，不用装客户端**：设置页点「打开扫码登录」，在本地登录页用微信扫码；
  插件自己轮询登录结果并接回，不读日常浏览器的 cookie。
- **额度可见**：Loomy 显示可用 / 永久 / 每日积分；小浣熊显示剩余积分。
- **两套设置页**：Loomy、商汤小浣熊各自独立的模型开关、上下文窗口与登录卡片。

> 非官方插件。两家都是网页 / 客户端私有接口，不是官方开放 API；上游升级后协议可能变化。

## 为什么需要它

两家都没有面向个人用户的开放 API。网页版登录后的会话不能直接当模型网关凭据，桌面客户端
又把登录态锁在自己的文件里，插件拿不到可用的令牌。

插件因此在宿主侧起一个本地登录页：页面上是真正的微信登录二维码，Loomy 走讯飞账号接口拿
`session`，小浣熊走服务端签发的扫码会话拿令牌。全程由宿主轮询，不依赖浏览器回调，也不
接收密码。拿到凭据后，模型调用走两家都兼容的 OpenAI Chat Completions 协议；插件负责把
DSH 的消息、图片、工具调用与思考流翻译成对应格式。

## 安装

**插件 → 添加插件**，填 `dsh-llm-adapters` 并安装（npm）；也可以从
`github:k1-h2/dsh-llm-adapters` 或本地目录安装。装完按提示**重启 DSH**。

## 登录

**设置 → Loomy** 或 **设置 → 商汤小浣熊** → 点「打开扫码登录」。浏览器会打开一个本地
登录页，用微信扫码并在手机上确认即可；成功后账号、额度与模型列表随即刷新。

- **Loomy**：首次使用的微信账号会被要求在该登录页里绑定手机号（短信验证码），这是讯飞
  账号侧的要求；绑定完成后才会下发 `session`。
- **小浣熊**：二维码由官方服务端一次性签发，扫码确认后自动接回，没有额外表单；过期或已用过
  的码会明确提示，重新点一次即可换新码。
- 登录页由插件在本机临时提供，关闭窗口不会中断宿主侧的轮询；但重新打开需要点「重新打开
  登录页」。弹窗被浏览器拦截时也用这个链接。

排障与端口、凭据位置见 [常见问题](./FAQ.md)。

## 设置页

- **登录卡**：显示账号、到期时间与额度；未登录时可发起扫码登录，登录中可取消，也可退出登录。
- **模型清单**：来自账号实时目录，名称会归一化（`GLM-5-3` → `GLM 5.3`，倍率括号移除），
  其余括号内容转为标签；逐个启用 / 关闭，并可指定上下文窗口。思考档位与读图能力在每次刷新时
  按 OpenRouter 的公开模型表做通配匹配校正，匹配不到回退上游，再没有就全部开放。聊天框的模型
  菜单直接显示 `low` / `high` / `max` 等原始档位名。
- **高级设置**：分组名称、强制识图 / 纯文本模型、模型别名、默认输出上限。
- **供应商开关**：在插件管理页关闭某个供应商后，它的设置页、模型分组与 provider 路由一起移除。

再次打开页面时先显示上次快照，账号与模型在后台刷新。

## 用 YAML 配置

设置页之外，也可以直接写进 profile 的 `cordis.patch.yml`：

```yaml
- id: llm-adapters
  name: dsh-llm-adapters
  config:
    loomyEnabled: true
    raccoonEnabled: true
    loomyDisplayName: Loomy
    raccoonDisplayName: 商汤小浣熊
    loomyDisabledModels: []
    raccoonDisabledModels: []
    loomyModelContextWindows: {}
    raccoonModelContextWindows: {}
    defaultMaxTokens: 32000
```

两个 provider 的模型开关、窗口与别名是分开的字段；超时、缓存等运行参数共享。
