# dsh-llm-adapters

把 **Loomy（讯飞）** 与 **商汤小浣熊** 桌面客户端里的模型接入 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)。

不填 API Key，不复制 Token。插件只读取桌面应用自己已经写在本机的登录态：

- **Loomy**：`userData/auth-session.json`
- **商汤小浣熊**：`~/.box-agent/config/auth.json`（或 `BOX_AGENT_CONFIG_DIR` 指向的位置）

安装后，模型选择器里出现「Loomy」和「商汤小浣熊」两个分组；设置页与 `dsh-agent-sdk-bridge` 采用同一套结构：账户/额度卡片、模型开关、逐模型上下文窗口、高级设置。

> 非官方插件。两个上游都是客户端私有接口，不是官方开放 API；桌面应用升级后协议可能变化。

## 功能

- **复用本机登录**：不需要在 DSH 里再次登录，也不接受手动粘贴密码或 Token。
- **模型目录**：读取上游账号实际返回的模型，并显示读图能力、计费倍率、折扣/限免标签与上下文窗口。
- **额度**：Loomy 显示可用/永久/每日积分；小浣熊显示剩余积分。
- **模型开关与上下文窗口**：按模型启用/关闭，并可在不超过上游声明的前提下选择较小的上下文窗口。
- **小浣熊令牌续期**：访问令牌临近过期时自动刷新，并把轮换后的 access/refresh 令牌**原子回写**到桌面端自己的 `auth.json`。若没有回写，桌面端下次刷新会撞上 `refresh_conflict` 并掉登录。
- **图片输入**：按模型能力把图片转成 data URL；小浣熊使用逐模型实测的识图表，不盲信目录标签。
- **思考内容**：上游返回的 `reasoning_content` 会映射为 DSH 的 reasoning 流。

不包含签到、积分领取或登出操作。插件不会改动桌面应用的登录状态（小浣熊令牌刷新除外），也不会删除应用文件。

## 前置条件

1. 本机已安装并登录 **Loomy** 桌面客户端，或 **商汤小浣熊** 桌面端（只需使用其中一个也可）。
2. DSH 为 `0.2.x` 对应的 Web/Desktop profile。
3. Node.js `^22.19.0 || >=24.0.0`（DSH 自身要求）。

插件不启动桌面应用，也不代替应用登录。登录态缺失时，设置卡片会显示应检查的文件路径。

## 安装

### 从 npm

```sh
dsh plugin add dsh-llm-adapters
```

### 从源码 / 本地目录

```sh
git clone https://github.com/k1-h2/dsh-llm-adapters.git
cd dsh-llm-adapters
npm install
npm run build
dsh plugin add link:/absolute/path/to/dsh-llm-adapters
```

安装后重启 DSH（含托盘进程），再刷新页面。首次打开设置 → Loomy / 商汤小浣熊，应能看到本机登录态与模型列表。

## 设置页

- **账户卡**：显示登录态来源、账号（若登录态中提供）、到期时间与额度。点击「重新读取登录态」会在客户端重新登录后重新扫描文件。
- **模型列表**：搜索、只看已启用、全部启用/关闭、逐模型开关与上下文窗口。
- **高级设置**：分组名称、自定义登录态路径、强制识图/纯文本模型 ID、模型别名、默认输出上限。
- **供应商开关**：在插件管理页关闭某个供应商后，它的设置页、模型分组与 provider 路由都会移除；登录态与已保存选择保留。

所有配置写入走 DSH 的 `configForms` 修订栅栏，不经过插件自己的写接口。

## 凭据与隐私

| 项目 | Loomy | 商汤小浣熊 |
| --- | --- | --- |
| 登录文件 | `%PUBLIC%\Loomy\<安装ID>\userData\auth-session.json` | `~/.box-agent/config/auth.json` |
| 路径覆盖 | 高级设置，或环境变量 `LOOMY_AUTH_FILE` | 高级设置、`BOX_AGENT_CONFIG_DIR` 或 `RACCOON_AUTH_FILE` |
| 会话寿命 | 约 14 天，无 refresh token | access ≈ 3 小时，refresh ≈ 30 天 |
| 自动续期 | 不支持，过期后需在客户端重新登录 | 支持；刷新后回写应用文件 |
| 插件是否写入文件 | 否 | 仅回写轮换后的令牌，保留原文件其他字段 |

插件不会把令牌写入日志或设置页响应；设置接口只返回登录来源、账号字段、到期时间和额度。

## 已知限制

- 两个上游都是私有接口，可能随桌面端更新变化。最易变的是 Loomy 的追踪头/模型目录，以及小浣熊的 `auth.json` 字段与 refresh 单次使用语义。
- Loomy 在未给出 `finish_reason` 就发送 `[DONE]` 时存在静默截断。插件把这种结束标成 `max-tokens`，避免把半截回答当成正常完成。
- 小浣熊目录里的 `reasoning` 标签描述的是应用侧路由预设，插件不据此提供推理档位。思考文本仍会按上游实际返回透传。
- 小浣熊目录的识图标签已知会错。插件使用实测表（`RACCOON_MEASURED_VISION`），并允许用高级设置覆盖。
- 小浣熊的 `X-Org-Code` 目前按个人版留空；企业版未验证。
- Loomy 模型目录里的倍率从展示名称解析，上游若改格式可能丢失倍率显示；不影响调用。
- 同一个 refresh token 被多个进程同时刷新时，会由上游判定冲突。插件会先重读应用文件，不盲目重试。
